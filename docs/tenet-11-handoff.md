# TENET-11 handoff

Implemented a read-only BB findings page at `/plugins/tenet-status/findings/<threadId>`. The Pi thread header keeps its metadata-only summary and now has a Details button. Non-Pi threads do not get the header action. The owner RPC resolves the thread and machine through BB, then the host reader scans only that machine's configured private archive. No assessment, permission or agent-message API is used.

The page shows validated linked selected FAIL calls only. A separate five-candidate page RPC re-reads each call through the archive detail reader, capped at 64 stages and 16 MiB per candidate. It projects only call label, mode, timestamp, selected rule ID/severity/policy text/confidence, would-decision, actual permission, observed execution and missing stages. Text is length-limited and React-escaped. One metadata pass computes the linked candidates, count and gaps; per-call detail lookup stays within the candidate session. Missing or changed detail is omitted with a gap warning, which remains visible across pages until Refresh. The summary RPC still carries no detail, cursor or items. Unlinked historical recordings stay in the standalone inspector. Scans are incremental, so `unknown` and `partial` never mean an all-clear. Failed next-page requests hide the broken cursor and offer Refresh from page one. The sidebar's panel root explains how to open a thread's details rather than attempting a thread lookup.
