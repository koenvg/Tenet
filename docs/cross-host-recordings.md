# Reading Pi and Claude recordings together

The inspector accepts two archive formats. Schema 1 is historical Pi data: its directory and deep-link hashes remain `sha256(native session ID)` and `sha256(Tenet invocation ID)`. The reader attributes these records to Pi's main context, but their adapter capabilities were not recorded. Do not read that attribution as verified historical host coverage. The reader does not migrate or rewrite the files.

Production Pi and Claude adapters now write schema 2. A session directory hashes `[host, native session ID, execution context ID]`; an invocation link hashes those values plus the Tenet invocation ID. Native IDs shared between hosts or child contexts therefore get separate pages. New Pi links use the schema-2 hash; old links continue to open schema-1 records. Mixed directories need the current reader. Unknown versions, corrupt files and unsafe paths appear under Recording issues rather than silently becoming Pi records.

The inspector shows the adapter capabilities recorded at invocation time, not today's installed configuration. A policy ALLOW or released permission does not certify that Claude executed the tool or that its hooks covered every call. Successful and failed result events mark observed execution; without one, execution is unknown. Assessment, would-decision, permission and approval remain independent. Thresholds in older decisions use recorded contributions or the configuration captured with that invocation, never current settings.

Recording is best-effort. `TENET_RECORDING=off`, dormant sessions and the shared off switch suppress diagnostic capture; recording errors do not change a tool's permission. Stage snapshots retain the existing evidence redaction and byte limits, and the inspector has no approval or control endpoint. The Claude bridge's small eligibility file is separate from the diagnostic archive. Removing Claude hooks or stopping the bridge stops Claude interception; it does not erase old recordings. Rolling back to a Pi-only inspector can leave schema-2 files unreadable. Retain a copy of the current reader to inspect them, and never rewrite schema-1 archives to make a rollback work.
