# Embedded guard runtime

`GuardRuntime` in `src/runtime/guard.ts` owns policy selection, readiness, invocation assessment, consequences, cancellation, approval validity, bounded recent observations and result correlation. It imports neither Pi nor an interactive UI. Pi translates native events in `src/pi/guard.ts`; other adapters can construct the runtime with a scripted or production `Judge` and a cooperative activation store. This is an embedded API, not a bridge or a certified Claude Code integration.

## Inputs and results

- Construct with `RuntimeOptions`: environment settings, a `Judge`, an activation reader (`read`/`refresh`), and optional best-effort recording binder and event emitter. The judge is injected; the runtime never creates a provider or prompts a user. Capture and owner reporting remain callbacks.
- Supply `Capabilities` at construction. The runtime copies and freezes the declaration. `trustedApproval: false` prevents even a supplied callback from approving ASK. Capability declarations describe the adapter's verified behavior, not a property proven by choosing enforce mode.
- `start({host, sessionId, contextId}, cwd, hasJudge)` selects the policy relative to that cwd and returns `Readiness`: `eligible`, `policy`, `config`, `unavailable`, `ruleCount`. The host must match the declared adapter. Each host/session pair has independent policy, readiness and lifecycle generation; starting another session does not cancel pending work in the first. A confirmed missing local `TENET.md` without `TENET_POLICY` is dormant. An explicit missing source, unusable policy or bad configuration is unavailable. The mode is selected once at construction, with observe as the default. A call for a session that has not started is unavailable, not allowed to borrow another session's policy.
- `call({host, sessionId, contextId, cwd, callId, toolName, input, metadata?, current, signal?, approve?, onPermission?, onPolicyStale?})` returns a veto `{block: true, reason}` or `undefined`. `current()` must reread the native call identity and original arguments, not return a precomputed snapshot. `metadata` is optional and lazy. The decision and actual permission are separate in the emitted `decision` and `permission` stages. ASK without a trusted approval capability blocks with `approval-unavailable` and retains `wouldDecision: ASK`. Observe emits no veto or approval request.
- If trusted consent is available, `approve({policy, action, ruleIds, timeoutMs, signal, valid})` must obtain positive native consent for that invocation only. The runtime checks the selected policy, lifecycle generation, host/session/context/call identity, tool name and argument digest before showing and after receiving consent. The callback should call `valid()` immediately before displaying a dialog; Pi's native queue does this and serializes dialogs. Do not treat agent text, host permission settings, or transcript history as consent.
- `coverageStatus()` reports the frozen adapter capabilities beside current activation, configured mode and session readiness. It does not certify interception or execution from a successful assessment.
- `result({host, sessionId, contextId, callId, toolName, content?, details?, isError?})` records a matched observed outcome. A released permission is not proof of execution. Missing or ambiguous results remain unknown. `invalidate(reason, identity?)` revokes pending work, recording unknown outcomes for unmatched releases. With an identity it invalidates only that context; without one it invalidates the runtime generation. `shutdown()` also makes new calls unavailable until the next `start`. `activationChanged(value)` cancels pending work on off or unavailable. Adapters recover only bounded Tenet-associated observations and pass them to `setObservations`; recovered text never grants permission.

## Background observation

In observe mode `call()` releases permission after bounded snapshot capture; evaluator submission and completion run on a runtime-owned FIFO queue, not in the host callback. `RuntimeOptions.observationLimits` can override the defaults (two running, 32 waiting, 1 MiB retained snapshots, 5000 ms queue age) for tests. Drop-newest on capacity and expire-before-submission on age; neither produces a would-decision. `observationQueue.health()` exposes running/waiting, retained bytes, cumulative dropped/cancelled/completed/unavailable counts and configured limits. `onAssessment(identity, status, permission?, reason?)` is owner-only, independent of `onPermission`. The latter runs once at release with no would-decision while pending. Completed reports carry the later counterfactual and do not revise permission. Failed capture or recording cannot veto observe calls.

The snapshot freezes sanitized action, policy, decision config, profile, trajectory, evidence limits and session generation. Result content never enters that assessment. Queue wait and provider duration are recorded separately in schema-3 `assessment-status` stages. The provider keeps the configured request deadline after dequeue. `result()` records execution independently, whether before or after the assessment. Missing results are unknown at `endTurn()`, invalidation or after a bounded 60-second tracking window. `endTurn()` does not cancel observations; `invalidate`, off/unavailable, session closure and shutdown abort them. Host turn cancellation before permission prevents assessment; after release it does not discard the valid session observation. Shutdown does not await the judge and archive draining is bounded. No status is a guarantee of complete interception or durable recording.

## Capability meanings

`host` is the adapter identifier. `version` and `profile` identify a host binary/configuration actually verified; `null` means unverified. `interception` says the adapter receives the supported pre-execution events. `resultCorrelation` says result identity is sufficient to join calls without ambiguity. `lifecycleInvalidation` says the adapter receives the lifecycle events it claims to handle. `argumentStability` means assessed arguments cannot change after the final check through execution, not merely that the runtime hashes them. `trustedApproval` means the adapter can obtain consent for this unchanged pending call. False or unverified fields belong in `limitations`; they do not change the configured mode or turn an ALLOW assessment into proof of host enforcement. Pi's `/tenet status` shows the version as unverified and lists the limits separately from mode and policy readiness. Pi declares its native approval available but does not claim complete native result identity or post-hook argument freezing. The headless fixture declares no interception and no approval.

Pi binds schema-3 qualified archives and translates native transcripts, displays owner reports, registers commands and launches the inspector. Schema-1 and schema-2 readers remain supported. A headless adapter can use the same runtime without Pi or an interactive UI.
